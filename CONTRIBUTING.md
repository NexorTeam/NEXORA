# مشارکت در پروژه | Contributing

## فارسی
1. برای هر کار یک Issue یا مورد مشخص در `planning/backlog.md` ایجاد کنید.
2. هر قابلیت را در یک شاخه جدا توسعه دهید؛ برای مثال `feature/membership-management`.
3. نام شاخه‌ها و Commitها را کوتاه و انگلیسی نگه دارید.
4. قبل از ادغام، کد را اجرا و آزمون‌های مرتبط را بررسی کنید.
5. تغییرات مستندات را همراه با تغییرات قابلیت‌ها ثبت کنید.
6. هیچ رمز عبور، کلید API یا اطلاعات واقعی اعضای باشگاه را در مخزن قرار ندهید.
7. از داده‌های ساختگی برای نمایش و آزمون استفاده کنید.

## English
1. Track each task as an Issue or in `planning/backlog.md`.
2. Develop each feature in a separate branch, e.g. `feature/membership-management`.
3. Keep branch names and commit messages short and in English.
4. Run the application and relevant tests before merging.
5. Update documentation when behavior changes.
6. Never commit passwords, API keys, or real member data.
7. Use fictional data for demos and tests.

## Suggested commit format
- `docs: add requirements`
- `feat: add membership status`
- `fix: validate payment amount`
- `test: cover role permissions`
