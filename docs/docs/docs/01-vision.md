۱. معرفی پروژه

NEXORA سامانه‌ای وب‌محور برای مدیریت یکپارچهٔ فعالیت‌های باشگاه‌های ورزشی است. هدف آن فراهم‌کردن بستری منظم برای مدیریت اعضا، مربیان، برنامه‌های تمرینی، برنامه‌های تغذیه، اشتراک‌ها و سوابق پرداخت است.

این سامانه با درنظرگرفتن نیازهای مدیر باشگاه، مربی و ورزشکار طراحی می‌شود.

۲. مسئله و نیاز

مدیریت دستی اطلاعات اعضا، وضعیت اشتراک‌ها، برنامه‌های تمرینی و پرداخت‌ها می‌تواند زمان‌بر باشد و احتمال خطا یا پراکندگی اطلاعات را افزایش دهد.

NEXORA با هدف سامان‌دهی این اطلاعات، کاهش کارهای تکراری و آسان‌ترکردن دسترسی کاربران مجاز به اطلاعات مرتبط طراحی می‌شود.

۳. چشم‌انداز

ایجاد سامانه‌ای ساده، امن، توسعه‌پذیر و کاربرپسند که مدیریت روزمرهٔ باشگاه‌های ورزشی را آسان‌تر کند و دسترسی به اطلاعات را براساس نقش کاربران سامان دهد.

۴. اهداف اصلی

- یکپارچه‌سازی اطلاعات باشگاه، اعضا و مربیان
- مدیریت برنامه‌های تمرینی و تغذیه
- ثبت وضعیت اشتراک‌ها و پرداخت‌ها
- نگهداری سوابق مرتبط با فعالیت ورزشکاران
- فراهم‌کردن گزارش‌های مدیریتی
- کنترل دسترسی براساس نقش کاربران
- حفاظت از اطلاعات خصوصی هر باشگاه

۵. کاربران هدف

مدیر باشگاه (Gym Manager)

مدیریت اطلاعات باشگاه، اعضا، مربیان، اشتراک‌ها، پرداخت‌ها و گزارش‌ها.

مربی (Trainer)

مدیریت برنامه‌های تمرینی و تغذیهٔ ورزشکاران مجاز و مشاهدهٔ اطلاعات موردنیاز برای انجام وظایف خود.

ورزشکار (Athlete)

مشاهدهٔ برنامه‌های اختصاص‌یافته، وضعیت اشتراک و سوابق مرتبط با فعالیت‌های خود.

English Version

1. Project Overview

NEXORA is a web-based system intended to centralize the management of gym operations, including members, trainers, workout plans, nutrition plans, memberships, and payment records.

2. Problem Statement

Manual management of member records, memberships, training plans, and payments can be time-consuming and may lead to inconsistent or scattered information.
[10/31/2026 12:39 PM] 𝘼𝙢𝙞𝙧 𝙖𝙗𝙗𝙖𝙨 | 𝙂𝙝: NEXORA aims to organize these records, reduce repetitive administrative work, and provide authorized users with convenient access to relevant information.

3. Vision

To develop a simple, secure, maintainable, and user-friendly system that supports daily gym operations and organizes access according to user roles.

4. Objectives

- Centralize gym, member, and trainer records.
- Manage workout and nutrition plans.
- Track memberships and payment records.
- Maintain relevant athlete activity history.
- Provide basic management reports.
- Enforce role-based access control.
- Protect private data belonging to each gym.

5. Target Users

Gym Manager: Manages gym information, members, trainers, memberships, payment records, and reports.

Trainer: Creates and manages authorized workout and nutrition plans for assigned athletes.

Athlete: Views assigned plans, membership status, and relevant personal activity records.

6. Initial Scope

The initial version is planned to include authentication, role management, gym and member management, trainer management, an exercise library, workout plans, nutrition plans, membership tracking, manual payment records, workout history, and basic reports.

Manual payment recording does not imply integration with a real payment gateway.

7. Out of Scope

Unless approved later, the initial version excludes real online payments, standalone mobile applications, wearable-device integration, automated medical or nutritional advice, and advanced AI-based analysis.

8. Design Principles

- Security and privacy
- Ease of use
- Role-based authorization
- Isolation of private gym data
- Maintainable and testable code
- Documentation and testing
- Persian-first, right-to-left user interface

9. Proposed Technology Stack

Python, Django, HTML, CSS, Bootstrap, JavaScript, SQLite for initial development, Git, GitHub, and PlantUML.

The proposed stack must be confirmed with the instructor and team.

10. Success Criteria

The project should provide working role-based access, gym and member management, authorized workout-plan management, athlete access to assigned plans, accurate membership and payment records, and verified isolation between gyms.

Documentation and tests should reflect the actual implemented features.

11. Assumptions and Constraints

The project is developed by a three-member university team. Final requirements and technologies must align with the instructor's expectations. All demonstration data should be fictional, and planned features must not be described as implemented until verified.
