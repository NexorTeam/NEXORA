Roles are provisional and should be agreed by all members. Every member should contribute commits and be able to explain the system.

## Workflow
1. Record work as GitHub Issues or backlog tasks.
2. Assign an owner and acceptance criteria.
3. Create a feature branch.
4. Commit small, meaningful changes.
5. Open a Pull Request for review by another member.
6. Run tests and update documentation.
7. Merge only when the feature works and review is complete.

## Suggested weekly team meeting
- Completed tasks
- Blockers
- Upcoming tasks
- Decisions requiring instructor approval
- Test status and documentation changes

## Academic integrity
Record actual contributions accurately. Do not claim features, tests, approvals, or results that have not occurred.
